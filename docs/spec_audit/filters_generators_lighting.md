# Filter Effects Module Level 1, second half (feFlood to feTurbulence, lighting, light sources)

Part of the [W3C specification audit](../design_docs/0071-w3c_spec_audit.md). One row per element,
attribute, property, value and feature in scope. Findings come from reading Donner source at
revision `b39a524a2` and the specification versions listed below. No code was built or executed
for this ledger, so every behavioral claim is a code-reading result until a test confirms it. All
paths are relative to the repository root.


Scope: the elements feFlood, feGaussianBlur, feImage, feMerge, feMergeNode, feMorphology, feOffset, feTile, feTurbulence, feDiffuseLighting, feSpecularLighting, feDistantLight, fePointLight and feSpotLight, their element-specific attributes, and the algorithms and prose rules that define them. Every statement about Donner behavior is by code reading of the pinned source revision; nothing was built or run. Each row states behavior for both renderers: the CPU filter graph executor (donner/svg/renderer/FilterGraphExecutor.cc driving third_party/tiny-skia-cpp/src/tiny_skia/filter/) and the Geode GPU filter engine (donner/svg/renderer/geode/GeodeFilterEngine.cc with the WGSL programs in donner/gpu/shader/programs/).

## Inventory

Derivation: `el:` keys are the 14 lines of the SVG 2 CR element index for these elements. `attr:` keys are the 34 lines of the SVG 2 CR attribute index for these elements, one row each. `val:` keys were built from the attribute definitions of the TR: one row per enumerated keyword, per one-number and two-number form, and per stated zero, negative or range rule. `feat:filter-effects-1/` keys were built from the prose and the reference code of each section: one row per rule (kernel definition, approximation, each step of the turbulence reference code, each lighting equation and kernel case, placement and error rules, implementation limits). The property definition tables of flood-color, flood-opacity and lighting-color are owned by `filters_core.md`; here they appear only as the consuming feature rows. The common attributes x, y, width, height, result and in are owned by `filters_core.md` and are cited only where a primitive in this half has its own rule (feImage, feTile, feMergeNode).

Out of scope for an SVG user agent without script: the DOM interfaces of Appendix B and the tainting and timing rules of section 15 (rows `feat:filter-effects-1/dom-interfaces` and `feat:filter-effects-1/tainted-filter-primitives`).

### Divergences between the CPU executor and the Geode engine

All by code reading. Everything not listed here follows the same rule on both renderers (the parser, the filter graph builder in donner/svg/components/filter/FilterSystem.cc, the subregion model in donner/svg/renderer/FilterRegionContext.h and the resource limits are shared).

| Primitive | CPU executor | Geode engine | Row |
| --- | --- | --- | --- |
| feTurbulence, type=fractalNoise with numOctaves <= 0 | Writes 128/255 into all four premultiplied channels (third_party/tiny-skia-cpp/src/tiny_skia/filter/Turbulence.cpp:468-485): white at half alpha | Loop runs zero times, giving 0.5 per channel then premultiplied (donner/gpu/shader/programs/TurbulenceSource.h:125-130): the reference value | `val:numOctaves/zero` |
| feDiffuseLighting, feSpecularLighting border pixels | One-sided normal kernels at the filter raster border; the whole raster is lit, then clipped to the primitive subregion | One-sided kernels at the bounds of the input's primitive subregion; transparent black outside those bounds | `feat:filter-effects-1/lighting-surface-normal-edges` |
| feTile with fractional input subregion | Period is ceil(far edge) - floor(origin), origin clamped to the raster, transparent outside the raster | Period is ceil(size), origin not clamped, edge texel repeated outside the texture | `val:feTile/input-subregion` |
| feMorphology erode at the raster border | Samples beyond the raster are ignored (window truncated) | Samples beyond the texture count as transparent | `feat:filter-effects-1/feMorphology-kernel` |

Rules where both renderers share the same divergence from the TR: turbulence stitching, seed between 0 and 1, gradient setup and noise origin; lighting edge and corner factors; the SVG 1.1 specularExponent range; the expanded default subregion of feGaussianBlur and dilating feMorphology; a negative stdDeviation on one axis; integer snapping of feOffset, feMorphology and feTile; the resource limits.
