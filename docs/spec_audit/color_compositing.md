# Color, compositing and the rendering model

Part of the [W3C specification audit](../design_docs/0071-w3c_spec_audit.md). One row per element,
attribute, property, value and feature in scope. Findings come from reading Donner source at
revision `b39a524a2` and the specification versions listed below. No code was built or executed
for this ledger, so every behavioral claim is a code-reading result until a test confirms it. All
paths are relative to the repository root.


Scope: CSS Color 4, CSS Color 5, Compositing and Blending 1, the parts of CSS Images 3 that SVG uses, the SVG 2 CR
rendering model chapter, and the raster image requirements the CR places on viewers. Donner revision `b39a524a2`.
Every behavioral claim is a code-reading result: nothing was built or run. All Donner paths are relative to the
checkout root. Where the two renderers differ the row says so; "tiny-skia" is the CPU renderer and "Geode" the GPU
renderer.

CSS Color 5 is a Working Draft, so its rows describe a moving target. The CR cites the 2003 PNG edition, which has no
APNG, cICP or other Third Edition features.

## Inventory

How the inventory was derived:

- CSS Color 4: the table of contents (sections 3 to 17 and both appendices), the two property definition tables
  (`color`, `opacity`), every grammar production block in the page (`<color>`, `<alpha-value>`, `<hue>`, `rgb()`,
  `hsl()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color()`, the color space and hue interpolation
  productions), the named color table (148 rows, extracted and diffed by script), the 19 system color definitions and
  the 23 deprecated ones. Each grammar alternative, each predefined color space and each system color is a row; named
  colors are one grouped row backed by the scripted diff. `device-cmyk()` is not defined by this level and appears
  under Color 5.
- CSS Color 5: the table of contents and all grammar blocks: `color-mix()` (one row per interpolation color space and
  per hue method), relative color syntax (one row per function), `alpha()`, custom color spaces and `@color-profile`,
  `device-cmyk()`, `light-dark()`, `contrast-color()`.
- Compositing and Blending 1: the three property tables, the 16 `<blend-mode>` values, every Porter-Duff operator in
  section 9.1, and the prose rules of sections 3.1 to 3.3, 5 to 8 and 10. `plus-lighter` and `plus-darker` occur in the
  published page only inside linked test names, and knockout was removed, so those are recorded as not-applicable.
- CSS Images 3: the `<image>` and `<gradient>` productions, `image-rendering`, `object-fit`, `object-position` and
  `image-orientation` with their values. Out of scope for an SVG user agent: image-set and cross-fade (Level 4),
  layout of replaced elements in CSS boxes, and gradients as paint (SVG paint is `<paint>`, not `<image>`).
- SVG 2 render chapter: one row per rule or table line of sections 3.1 to 3.11 (definitions, the five non-rendered
  situations, display and visibility sentences, each stacking-context condition, the group rendering steps, each line
  of the overflow table).
- Raster formats: the viewer requirements in conform.html and the image element text in embedded.html, expanded into
  the PNG and JPEG decoder features that decide whether a valid file renders correctly.

Out of scope for a scriptless SVG user agent, and therefore not-applicable rows rather than gaps: CSS serialization
and CSSOM interfaces, the Canvas 2D compositing API, HTML-only stacking and style rules, print color workflows, and
forced-colors and color-scheme behavior.
