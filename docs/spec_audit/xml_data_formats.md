attribute, property, value and feature in scope. Findings come from reading Donner source at
revision `b39a524a2` and the specification versions listed below. No code was built or executed
for this ledger, so every behavioral claim is a code-reading result until a test confirms it. All
paths are relative to the repository root.

## Inventory

How it was derived:

- XML 1.0: every numbered production in the Recommendation (84 anchors, [1] to [89]) and
  every named well-formedness constraint (12). Productions are grouped where they form one
  construct (for example [18] to [21] CDATA, [45] to [51] element declarations, [52] to [60]
  attribute-list declarations, [61] to [65] conditional sections). Section-level rules with no
  production of their own (encoding, end-of-line handling, attribute-value normalization steps,
  entity treatment tables 4.4 and 4.5, conformance and fatal errors) get `feat:xml/...` rows.
- Out of scope for a non-validating processor, and why: the 25 validity constraints (only a
  validating processor checks them); productions [84] to [89] (orphaned in the Fifth Edition,
  no longer used by any other production); external subset, external parsed entities and
  conditional sections are listed once each as not-applicable because a non-validating processor
  may decline to read external entities.
- Namespaces in XML: the four namespace constraints, the declaration, scoping, defaulting and
  qualified-name sections, the processor conformance section, plus how Donner maps namespaces to
  SVG elements and attributes.
- xml-stylesheet: the PI definition, the pseudo-attribute grammar, each of the six
  pseudo-attributes, and the processing rules.
- SVG 2 linking 16.1 (definitions, XLink attributes, the five processing steps, each bullet of
  valid URL targets) and 16.3 fragment identifiers as one row. The `a` element (16.2) and the
  `view` element belong to the structure and embedded-content ledgers.
- SVG 2 conformance: the well-formedness, error-processing, interpreter, data URL and compression
  requirements. Processing-mode feature tables, rendering accuracy and the DOM belong to other
  ledgers.
- Media type registration: type recognition, charset, fragment identifiers.
