# SVG 2 text chapter: elements, attributes, SVG-defined properties and layout rules

Part of the [W3C specification audit](../design_docs/0071-w3c_spec_audit.md). One row per element,
attribute, property, value and feature in scope. Findings come from reading Donner source at
revision `b39a524a2` and the specification versions listed below. No code was built or executed
for this ledger, so every behavioral claim is a code-reading result until a test confirms it. All
paths are relative to the repository root.


Item-by-item ledger for the SVG 2 text chapter (text, tspan, textPath, their
attributes, the properties the chapter itself defines or adapts, and every layout rule). Donner
evidence is `path:line` relative to the repository root at revision `b39a524a2`. Nothing was built
or executed: every behavior statement is a result of reading code, and a row is `conformant` only
when the implementing code was read and a named test asserts the behavior.

Donner has two text backends that share one layout engine (`donner/svg/text/TextEngine.cc`): a basic
backend (`TextBackendSimple`, stb_truetype: character map, advances, pair kerning) and a HarfBuzz
backend (`TextBackendFull`). "Both backends" in a row means the shared engine decides the behavior.
Differences are stated where they exist; the recurring one is that the basic backend forms no
ligatures and does no complex shaping, so reference cases that need shaping run on the HarfBuzz
backend only ("full backend only").

CSS Text, CSS Fonts, CSS Writing Modes, CSS Inline Layout and CSS Text Decoration properties are
defined in their own specifications and are audited in `text_font_properties.md`. This ledger references them only
where the SVG chapter adds or changes a rule (for example the removed keywords of
`dominant-baseline`, or SVG's percentage rule for `word-spacing`).

## Tests to create

- `attr:x@text`, `attr:y@text`, `attr:dx@text`, `attr:dy@text` (https://www.w3.org/TR/2026/CR-SVG2-20261006/text.html#ResolveGlyphPositioning): `<text x="10 bogus 90">ABC</text>` parsed from a document; expected per spec: the attribute is invalid and all three characters flow from 0.
- `attr:x@tspan` (same anchor): `<text font-size="10"><tspan font-size="40" dx="1em">A</tspan></text>`; expected shift 40, not 10.
- `attr:rotate@text` (#TextElementRotateAttribute): `rotate="10deg 20"` parsed from a document; expected invalid.
- `attr:href@textPath` and `feat:svg2/textpath-href-over-xlink-href` (#TextPathElement): textPath with `xlink:href` after `href`, pointing at different paths; expected `href` wins in either attribute order.
- `attr:path@textPath` (#TextPathElementPathAttribute): `path="M 10 10"` with a valid `href`; expected fallback to `href`.
- `attr:startOffset@textPath` and `feat:svg2/text-algo-path-offset-pathlength` (#TextLayoutAlgorithm): referenced path of length 200 with `pathLength="100"` and `startOffset="50"`; expected start at the midpoint. Second case: `startOffset="2em"` under `font-size="30"`.
- `el:textPath` (#elementdef-textPath): `<text><a href="#"><textPath href="#p">X</textPath></a></text>`; expected the text renders on the path.
- `prop:inline-size` (#InlineSizeProperty): vertical text with `inline-size: 50%` in a 400 by 200 viewport; expected measure 100. Second case: `inline-size: -10px` is an invalid declaration.
- `prop:text-overflow`, `val:text-overflow/clip`, `val:text-overflow/ellipsis` (#TextOverflowProperty): the CR example (three lines, inline-size 100, white-space pre).
- `prop:line-height` (#LineHeightProperty): two-line `white-space: pre` text with `line-height: 2`; expected baseline distance of twice the font size.
- `prop:vertical-align` (#BaselineShiftProperty): `vertical-align: super` on a tspan equals `baseline-shift: super`.
- `val:dominant-baseline/use-script`, `/no-change`, `/reset-size`, `val:alignment-baseline/auto`, `/before-edge`, `/after-edge`, `val:baseline-shift/baseline` (#DominantBaselineProperty, #AlignmentBaselineProperty, #BaselineShiftProperty): each as a declaration after a valid one; expected the earlier valid value survives.
